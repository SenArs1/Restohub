# Restohub

Электронное меню для планшетов с интеграцией iikoCloud. Первый объект — кондитерская **Madi Cake**.

Состав меню, цены, размеры, КБЖУ и наличие (стоп-лист) приходят из **iikoCloud**. Фото, описания
для гостей, метки и порядок редактируются в **админке Restohub** и попадают на планшеты после публикации.
Само меню для гостей — веб-приложение (PWA), которое открывается на планшетах в полноэкранном режиме.

```
iikoWeb: внешнее меню, стоп-лист ──► iikoCloud API ──┐
                                                     ├─► сервер Restohub ──► планшеты (PWA, офлайн-кеш, SSE)
админка /admin: фото, тексты, метки, порядок ───────┘   снимок iiko + SQLite + фото на диске
```

Подробно об архитектуре и этапах — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт

Нужен Node.js 22.5+ (встроенный SQLite). Зависимости: `sharp` (обработка фото), `preact` и `htm` (админка).

```bash
npm install
cp .env.example .env
npm run admin:user -- anna owner   # пользователь админки; пароль будет выведен один раз
npm run demo                       # демо-данные без iiko → меню http://localhost:8080, админка /admin
npm test
```

## Подключение к iiko (по плану)

| Шаг | Что делаем | Как проверить |
|---|---|---|
| 1. iikoWeb | Внешние заказы → Внешние меню: есть ли меню «Madi Cake»; если нет — создать, добавить категории, блюда, фото, описания | `npm run iiko:check`, пункт 3 |
| 2. iikoCloud API | iikoWeb → Настройки → Облачное API: создать API-ключ с доступом к организации Madi Cake, вписать его в `IIKO_API_LOGIN`. Для ключа нового формата также создать приложение типа server-to-server на портале разработчика iiko и указать `IIKO_CLIENT_SECRET` и `IIKO_APP_ID` | `npm run iiko:check`, пункты 1–2 |
| 3. Получение данных | Сервер забирает категории, блюда, цены, описания, веса, КБЖУ, аллергены и фото через `/api/2/menu/by_id` | `npm run iiko:check`, пункт 5; затем `npm start` |
| 4. Меню | `public/` — интерфейс под планшеты в стиле кондитерской | открыть `http://<сервер>:8080` на планшете |
| 5. Синхронизация | Опрос iiko каждые `SYNC_INTERVAL_MIN` минут, мгновенная рассылка планшетам, офлайн-кеш | `GET /api/status` |

Ключи старого формата получают токен через `/api/1/access_token` (только `apiLogin`), ключи нового
формата — через `/api/v2/access_token` (`apiKey` + `clientSecret` + `appId`). Если секрет не задан, а ключ
нового формата, `iiko:check` прямо об этом скажет.

`npm run iiko:check` в конце выводит `IIKO_ORGANIZATION_ID` и `IIKO_EXTERNAL_MENU_ID` — их лучше
зафиксировать в `.env`, чтобы не зависеть от переименований.

Если сервер выходит в интернет через HTTP-прокси (переменные `HTTPS_PROXY`), запускайте Node с
`NODE_USE_ENV_PROXY=1` — встроенный `fetch` по умолчанию прокси не использует.

## Проверка цен (до обещаний клиенту)

Изменение цены в основной номенклатуре iiko **не всегда** автоматически попадает во внешнее меню —
это зависит от настроек меню и категории цен. Перед тем как обещать автоматическое обновление цен:

```bash
npm run iiko:prices             # снимок «до» и список расхождений номенклатура ↔ внешнее меню
# меняем цену тестового блюда в iiko (приказ об изменении цен)
npm run iiko:prices -- --diff   # повторяем через 5 / 15 / 60 минут
```

Если номенклатура изменилась, а внешнее меню нет — скрипт пометит это `⚠ внешнее меню НЕ обновилось`.

### Результат проверки на Madi Cake (20.10.2026)

Цену тестового блюда «Дорадо» поменяли с 900 на 901 ₽:

| Что | Когда |
|---|---|
| Новая цена в облачной номенклатуре iiko | через ~8–10 минут после смены |
| Новая цена во внешнем меню | **не появилась сама** — за 17 минут наблюдения осталась 900 ₽ |
| После ручного обновления цены в карточке блюда внешнего меню | 901 ₽ сразу, Restohub отдал её при следующей синхронизации |

**Автоматическая сверка.** При каждой синхронизации Restohub сравнивает цены внешнего меню с
номенклатурой iiko. Расхождения видны на странице **`/status.html`** (например, `http://<сервер>:8080/status.html`)
и в логе сервера: «Дорадо: в iiko 950, во внешнем меню 900 — обновите цену в карточке блюда».
Если задана категория цен (`IIKO_PRICE_CATEGORY_ID`), сверка отключается — там цены отличаются намеренно.

**Регламент для заведения:** после изменения цен в iiko обновить цену в карточке блюда во внешнем меню
iikoWeb (Внешние заказы → Внешние меню). Restohub подхватит изменение в течение `SYNC_INTERVAL_MIN`
минут или сразу — через `POST /api/sync`.

## Админка

`http://<сервер>:8080/admin` — работает на компьютере и на телефоне.

- **Блюда.** Слева — категории и блюда из iiko, с поиском и фильтрами: «Без фото», «Скрытые»,
  «Закончились», «Цена расходится», «Изменено». Справа — редактор: название и описание для гостей
  (пусто — берутся из iiko), метки («Хит», «Новинка», «Сезонное», «Без глютена», «Без сахара», «Веган»),
  «Скрыть на планшетах», фото (до 10, первое — главное). Блок «Из iiko» — только просмотр: цены,
  размеры, выход, КБЖУ, аллергены, наличие.
- **Категории.** Подзаголовок, скрытие, обложка, порядок блюд; отдельно — порядок категорий.
- **Фото.** JPEG, PNG или WebP до 20 МБ. Сервер поворачивает по EXIF, удаляет метаданные и делает копии
  400/800/1600 px в WebP и JPEG; планшет загружает нужный размер. HEIC не поддерживается — на iPhone
  выберите «Наиболее совместимый» формат камеры (при загрузке через браузер iPhone обычно сам отдаёт JPEG).
- **Черновик и публикация.** Все правки сначала сохраняются в черновик. «Предпросмотр» показывает
  меню по черновику в рамке планшета. «Публикация» — список изменений, комментарий, кнопка
  «Опубликовать на планшеты», отмена черновика и история с откатом к любой прошлой публикации.
- **Стоп-лист.** Проверяется раз в `STOPLIST_INTERVAL_SEC` секунд и применяется сразу, без публикации.
  В «Настройках» выбирается, что делать с закончившимся блюдом: показывать с пометкой «Закончилось»
  (по умолчанию) или скрывать. Если закончился только один размер, он помечается отдельно.

Пользователи создаются на сервере: `npm run admin:user -- <логин> [owner|manager] [--password=...]`.
Повторный запуск с тем же логином меняет пароль и завершает старые сессии. Вход: пароль на scrypt,
cookie `HttpOnly` + `SameSite=Strict`, после 10 неудачных попыток вход блокируется на 15 минут.
Если админка открыта через HTTPS, включите `COOKIE_SECURE=1`.

## Как устроена синхронизация

- **Сервер** раз в `SYNC_INTERVAL_MIN` минут забирает внешнее меню и сохраняет **снимок iiko**
  (`data/iiko-snapshot.json`). Стоп-лист — раз в минуту.
- **Меню для планшетов** собирается из снимка iiko, опубликованного контента админки и стоп-листа.
  Если версия (хеш) изменилась — планшеты получают событие и обновляются.
- **Фото iiko** скачиваются в `data/media/` и показываются, пока у блюда нет своих фото из админки.
- **iiko недоступен** — сервер продолжает отдавать последнее сохранённое меню (переживает перезапуск).
- **Планшеты** получают событие по SSE (`/api/events`) и перезагружают меню без перезапуска страницы;
  запасной вариант — опрос каждые 5 минут и при возврате сети.
- **Нет сети на планшете** — service worker отдаёт оболочку и фото из кеша, меню берётся из
  `localStorage`; внизу появляется плашка «Нет связи. Показано меню от …».
- Позиции без цены и скрытые во внешнем меню на планшетах не показываются.

Ручная синхронизация (например, сразу после смены цен):

```bash
curl -X POST -H "X-Admin-Token: $ADMIN_TOKEN" http://localhost:8080/api/sync
```

## Режим киоска на планшете

- Открыть меню в Chrome → «Добавить на главный экран» (запускается без адресной строки),
  или использовать kiosk-лаунчер (Fully Kiosk Browser и т.п.).
- Экран не гаснет (Screen Wake Lock), через `IDLE_SECONDS` бездействия меню закрывает карточку
  и возвращается к началу.
- Вёрстка адаптируется под альбомную и портретную ориентацию.

## API сервера

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/menu` | Меню (поддерживает `ETag` / `If-None-Match`) |
| GET | `/api/status` | Источник, время последней синхронизации, ошибка, число подключённых планшетов, сверка цен (`priceCheck`) |
| GET | `/api/events` | SSE-поток событий `menu` с версией |
| POST | `/api/sync` | Принудительная синхронизация (заголовок `X-Admin-Token`) |
| GET | `/api/menu?preview=1` | Меню по черновику (только после входа в админку) |
| | `/api/admin/*` | API админки: вход, состояние, правка блюд и категорий, порядок, фото, настройки, публикация, откат |

## Данные и резервные копии

Всё состояние — в папке `DATA_DIR` (по умолчанию `./data`):

- `restohub.db` — SQLite: черновик, история публикаций, сведения о фото, пользователи и сессии;
- `media/` — обработанные фото (из админки и скачанные из iiko);
- `iiko-snapshot.json` — последний снимок меню iiko.

Для резервной копии достаточно ежедневно копировать эту папку целиком (для `restohub.db` — командой
`sqlite3 data/restohub.db ".backup backup.db"` или при остановленном сервере).
