# Пилотный запуск Restohub в Madi Cake

Как установить сервер и планшеты, какой регламент дать персоналу и что проверить на месте.

## 1. Сервер

**Рекомендуется облачный сервер** (VPS с Ubuntu 24.04, 1 vCPU, 1 ГБ RAM, 10 ГБ диска) с доменом,
например `menu.madicake.ru`. Так проще всего получить HTTPS, а без интернета в зале планшеты работают
на своём кеше. Мини-ПК в зале тоже возможен, но HTTPS для локального адреса настроить сложнее (см. 1.4).

### 1.1. Установка

```bash
# Node.js 22.5+ (например, из https://nodejs.org или nodesource)
sudo useradd -r -m -d /opt/restohub restohub
sudo -u restohub git clone https://github.com/SenArs1/Restohub /opt/restohub/app
cd /opt/restohub/app
sudo -u restohub npm ci --omit=dev
sudo -u restohub cp .env.example .env    # заполнить ключи iiko, см. README
sudo -u restohub npm run iiko:check      # проверка доступа к iiko; вписать id в .env
sudo -u restohub npm run admin:user -- olga owner   # пароль будет выведен один раз
```

В `.env` для пилота: `HOST=127.0.0.1`, `PORT=8080`, `TRUST_PROXY=1` (сервер за Caddy),
`BACKUP_DIR=/var/backups/restohub` (лучше отдельный диск или смонтированное хранилище).

### 1.2. Автозапуск (systemd)

`/etc/systemd/system/restohub.service`:

```ini
[Unit]
Description=Restohub
After=network-online.target
Wants=network-online.target

[Service]
User=restohub
WorkingDirectory=/opt/restohub/app
ExecStart=/usr/bin/node server/index.js
Restart=always
RestartSec=5
# Если сервер выходит в интернет через HTTP-прокси:
# Environment=NODE_USE_ENV_PROXY=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now restohub
journalctl -u restohub -f        # лог: синхронизация, стоп-лист, предупреждения о ценах, копии
```

### 1.3. HTTPS через Caddy (рекомендуется)

Caddy сам получает и продлевает сертификат Let's Encrypt. DNS-запись `menu.madicake.ru` → IP сервера.

`/etc/caddy/Caddyfile`:

```
menu.madicake.ru {
    reverse_proxy 127.0.0.1:8080 {
        flush_interval -1   # SSE: обновления меню доходят до планшетов сразу
    }
}
```

С `TRUST_PROXY=1` Restohub берёт протокол и IP клиента из заголовков Caddy: cookie админки получают флаг
`Secure`, включается HSTS, лимит попыток входа считается по настоящему IP.
**Не включайте `TRUST_PROXY=1`, если порт Restohub доступен напрямую из сети**, — тогда эти заголовки
можно подделать. При `HOST=127.0.0.1` сервер доступен только через Caddy.

### 1.4. Мини-ПК в зале

Варианты HTTPS для локального адреса:
- встроенный HTTPS: `TLS_CERT_FILE` и `TLS_KEY_FILE` в `.env` (PEM). Сертификат должен быть
  доверенным для планшетов: например, домен `menu.madicake.ru`, который в локальной сети указывает на
  мини-ПК, и сертификат Let's Encrypt, полученный через DNS-проверку;
- собственный центр сертификации, установленный на каждый планшет, — работает не во всех версиях
  Android и браузеров, проверять на конкретном планшете.

Без доверенного HTTPS планшет покажет внизу подсказку «Меню открыто без HTTPS: офлайн-режим не работает».

## 2. Планшеты

1. Chrome последней версии (Android) или Safari (iPad).
2. Открыть `https://menu.madicake.ru/` → дождаться загрузки меню.
3. Открыть `https://menu.madicake.ru/?diag=1`: внизу «офлайн-фото: N/N» — фото загружены. После этого
   вернуться на адрес без `?diag=1`.
4. «Добавить на главный экран» или киоск-лаунчер (например, Fully Kiosk Browser с этим адресом).
5. Android: отключить экономию батареи для браузера или лаунчера, включить закрепление экрана; планшет
   на зарядке. Экран не гаснет сам (Screen Wake Lock), но системный таймаут лучше поставить максимальным.
6. Проверка офлайна: выключить Wi-Fi, закрыть браузер, открыть снова — меню и фото на месте, внизу
   «Нет связи. Показано меню от …».

## 3. Регламент для заведения

- **Смена цен.** Изменили цену в iiko → обновите цену в карточке блюда во внешнем меню iikoWeb
  (Внешние заказы → Внешние меню). Сама она туда не попадает (проверено 20.10.2026). Если забыть —
  в админке Restohub появится красное предупреждение «Цены расходятся», на планшетах будет старая цена.
- **Стоп-лист.** Ведётся в iiko как обычно; на планшетах обновляется в течение минуты.
- **Фото и тексты.** Менеджер правит в админке → «Предпросмотр» → «Публикация». Неудачную публикацию
  владелец откатывает в «Публикации → История».
- **Предупреждения в админке.** Красные — гости видят неверные или устаревшие данные, разобраться в
  тот же день; жёлтые — проверить, если повторяются. Значения — в README, раздел «Предупреждения».
- **Удержанное меню.** Если iiko прислал сильно сокращённое меню, планшеты остаются на прежнем.
  Проверить внешнее меню в iikoWeb; если сокращение настоящее — владелец нажимает «Применить новое меню».
- **Резервные копии.** Автоматически раз в сутки. Раз в неделю проверить копию («Настройки → Резервные
  копии → Проверить») и унести копию с сервера (`tar czf …`, см. README).
- **Пароли.** Сотрудникам — отдельные учётные записи; при увольнении — удалить пользователя.

## 4. Что проверить на пилоте

Автотесты и E2E в Chromium это покрывают на эмуляции; ниже — то, что можно подтвердить только на месте.

### 4.1. На реальном планшете

- [ ] Меню открывается по HTTPS, service worker регистрируется (`?diag=1` показывает «офлайн-фото: N/N»).
- [ ] Офлайн после перезапуска браузера и после перезагрузки планшета: меню и все фото на месте.
- [ ] Экран не гаснет в течение смены (Wake Lock + настройки системы); через `IDLE_SECONDS` меню
      возвращается к началу.
- [ ] Киоск-режим: гость не может выйти из меню; после перезагрузки планшета меню открывается само.
- [ ] Прокрутка и открытие карточек плавные на полном меню с фото; качество фото на экране планшета.
- [ ] Альбомная и портретная ориентация на реальном размере экрана.
- [ ] После пропадания Wi-Fi и возврата планшет сам получает новые публикации (SSE переподключается).
- [ ] Хватает места под фото: `?diag=1` без «не хватает места».
- [ ] Старые Android-планшеты: поддержка WebP (если нет — грузятся JPEG, это предусмотрено).

### 4.2. С доступом к действующему iiko (нужно разрешение на изменения в iiko)

- [ ] Поставить блюдо в стоп-лист → на планшете «Закончилось» в течение минуты; убрать → снова в продаже.
- [ ] Стоп по одному размеру блюда с несколькими размерами (если такие будут во внешнем меню).
- [ ] Сменить цену в номенклатуре → через ~10 минут красное предупреждение в админке; обновить цену во
      внешнем меню → предупреждение исчезает, на планшете новая цена.
- [ ] Фото из iiko: сейчас ссылки внешнего меню отдают 404 (файлов нет в хранилище iiko); после
      повторной загрузки фото в iikoWeb убедиться, что Restohub их скачивает.
- [ ] Полное меню (сейчас во внешнем меню 1 блюдо): объём, время синхронизации, фото для всех блюд.
- [ ] Сутки работы: токен iikoCloud обновляется сам, нет ошибок в логе и предупреждений «устарели».
- [ ] Нагрузка на iiko: стоп-лист раз в минуту, меню раз в 5 минут — нет ограничений со стороны iiko.

### 4.3. Инфраструктура

- [ ] HTTPS-сертификат продлевается (Caddy делает сам); админка открывается только по HTTPS.
- [ ] Перезагрузка сервера: Restohub стартует сам, планшеты переподключаются.
- [ ] Восстановление из копии на тестовой машине по README (проверка, что копии пригодны).
- [ ] Копии уходят с сервера (другой диск или хранилище).
